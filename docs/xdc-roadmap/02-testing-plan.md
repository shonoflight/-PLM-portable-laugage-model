## 1. Testing principles

1. **Correctness before size.** No output ships unless it decompresses to the exact original bytes using **several independent decoders**.
2. **Deterministic output.** The same input and settings must give the same bytes, regardless of thread count or machine.
3. **Measure against real tools.** Every size or speed claim is compared with Zopfli, ECT, libdeflate level 12, 7-Zip and `zip -9`.
4. **Real apps.** `iris-timesheet-xdc` is always in the test set.
5. **Automate it.** Everything except testing inside real messengers runs in CI (`cargo test`, plus benchmarks run on a schedule).

## 4. Correctness tests

### 4.1 Round-trip with several decoders
Every compressed stream is decoded by **all** of these and compared byte-for-byte:

1. `miniz_oxide` (pure Rust)
2. `flate2` with the zlib backend (C zlib)
3. `libdeflater` (libdeflate)
4. For `.xdc` files: `unzip -t` and Python `zipfile.ZipFile.testzip()`

A failure in any decoder fails the test.

### 4.2 Property tests (`proptest`)
- For any `Vec<u8>` (0–256 KB) and any setting combination: `inflate(compress(x)) == x`.
- Output must be no larger than stored size + 5 bytes per 65,535-byte block (incompressible input must never grow).
- `compress(x)` is deterministic: two runs give the same bytes, with 1 thread and with N threads.

### 4.3 Edge-case inputs (C4)
| Case | Why |
|---|---|
| Empty input, 1 byte, 2 bytes, 3 bytes | Minimum match length boundaries |
| 1 MB of `0x00` | Long runs, distance 1 |
| Repeating 258-byte and 259-byte patterns | Maximum match length |
| Pattern repeated exactly 32,768 and 32,769 bytes apart | Window edge |
| Random bytes | Must fall back to stored |
| Alternating random/compressible 64 KB chunks | Block splitting |
| All 256 byte values once | Full literal alphabet |
| Input of exactly 65,535 and 65,536 bytes | Stored block size limit |

### 4.4 Fuzzing (`cargo-fuzz`)
| Target | Check |
|---|---|
| `fuzz_compress` | Round-trip equality with `miniz_oxide` |
| `fuzz_zip_writer` | Output passes Python `zipfile` and `unzip -t` |
| `fuzz_bitwriter` | No panics; output length matches bits written |

Run time: 10 minutes per target in nightly CI, and 1 hour before each release.

## 5. Compression-ratio benchmarks

### 5.1 Comparison tools
`zip -9`, `zopfli --i15`, `zopfli --i1000`, `ect -9`, `libdeflate -12`, `7z -mx=9 -mm=Deflate`, `advzip -4`, and `xdc-squeeze` at each setting level.

### 5.2 Measurements (recorded to `bench/results.csv`)
| Column | Meaning |
|---|---|
| `corpus,file,tool,level` | What was tested |
| `raw_bytes,out_bytes,ratio` | Size |
| `compress_ms,decompress_ms` | Speed (median of 5 runs) |
| `peak_rss_kb` | Peak memory |
| `threads` | Thread count |

### 5.3 Whole-`.xdc` benchmark
For `iris-timesheet-xdc` and each C3 app, compare whole `.xdc` size:
- `zip -9` (the current `build.sh`): **baseline 363,516 bytes for iris-timesheet**
- `advzip` recompress
- `xdc-squeeze` default, and `xdc-squeeze --max`

### 5.4 Micro-benchmarks (`criterion`)
`match_finder` throughput (MB/s), `parser` per pass, `huffman` build time, full `compress` per level.

## 6. Performance and resource tests

| Test | Limit |
|---|---|

| Scaling to 1/2/4/8 threads | Speed-up ≥ 0.6 × thread count on Silesia |
| Worst-case time (all-zero 50 MB input) | No more than 3× the time for typical input |
| No unbounded recursion | Block-splitting recursion depth is capped |

## 8. Tests for the other tracks

### Track A — webxdc apps
- Unit tests for app logic (for example `model.js`, `schedule.js`) using Node's test runner.
- Multi-user sync in `webxdc-dev`: 3 simulated users, updates arrive out of order, everyone ends up in the same state.
- Realtime module: check that the feature-detection fallback works when `joinRealtimeChannel` is missing.

### Track B — privacy (configuration)
- Checklist: the chatmail account has a random address; the proxy is on (check the server log shows the proxy's IP); realtime is off by default in apps.
- Packet capture (Wireshark) while using an app: confirm no direct peer IP traffic when realtime is off.

### Track C — hybrid transport (design only)
- If prototyped: test dedup (the same update ID arriving over both paths is applied once), ordering, and a drill where the fast path drops 100% of traffic.

### Track E — shared library cache (proposal)
- Data needed: the share of bytes in C3 apps that comes from common libraries (counted by SHA-256 of vendor files).

## 9. Acceptance criteria per phase

| Phase | Must pass | Target |
|---|---|---|
| 0 Benchmark harness | `bench/results.csv` produced for C1–C3 with all comparison tools | — |
| 1 Packer (existing encoders) | All of §4.1 for `.xdc`; I1 passes; output deterministic | `iris-timesheet.xdc` ≤ `advzip` size |
| 2 Own encoder (correct output) | §3, §4.1–4.4 all green; 1 h of fuzzing clean | Within 5% of `zip -9` |
| 3 Optimal parser | All above | Within 1% of `zopfli --i15`, at least 3× faster |
| 4 DP split + header tuning | All above | ≤ `zopfli --i15` size on C1 and C3 |
| 5 Faster match finder + multi-core | All above + §6 | ≥ 10× faster than `zopfli --i15` at the same or smaller size |
| Release | I1–I6 manual checklist done | — |

**Regression rule (CI):** any change that makes the C1+C3 total more than **0.1%** bigger, or more than **10%** slower, fails CI unless explicitly approved.
